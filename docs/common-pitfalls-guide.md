## 1. 全体共通の地雷ポイント

### 💣 地雷1：要件が曖昧なまま進める

#### 失敗パターン
- クライアントの要望を深掘りせず、表面的な理解で進める
- 「効率化してほしい」という抽象的な要望だけで進める
- 目的・目標が不明確なまま作業を開始

#### 失敗例
```
クライアント：「業務を効率化してほしい」
コンサルタント：「わかりました。では分析を始めます」
→ 何を目指しているのか不明確なまま進む
→ 最終的に「期待と違う」と言われる
```

#### ✅ 対策
- **必ず要件定義を明確にする**
  - 「効率化」→「何を」「どのくらい」「いつまでに」を明確に
  - 成功の定義（KPI）を設定
  - 要件定義書を作成し、承認を得る

#### チェックリスト
- [ ] 目的が明確か？（何を達成したいか）
- [ ] 目標が数値化されているか？（どのくらい改善するか）
- [ ] 期限が明確か？（いつまでに）
- [ ] 成功の定義が共有されているか？

---

### 💣 地雷2：ステークホルダーを把握していない

#### 失敗パターン
- 決定権者を特定せずに進める
- 関係者を洗い出さず、後から反対される
- 現場の意見を聞かず、経営層の意見だけを聞く

#### 失敗例
```
経営層：「AIを導入したい」
コンサルタント：「わかりました。提案書を作成します」
→ 現場の意見を聞かずに進める
→ 提案書を提出したら「現場が反対している」と言われる
```

#### ✅ 対策
- **最初にステークホルダーマップを作成**
  - 決定権者を特定
  - 影響力・関心度を整理
  - 全関係者にヒアリング

#### チェックリスト
- [ ] 決定権者は誰か？
- [ ] 関係者は全員洗い出せたか？
- [ ] 現場の意見は聞いたか？
- [ ] ステークホルダーマップを作成したか？

---

### 💣 地雷3：記録を残さない

#### 失敗パターン
- 会議の議事録を残さない
- 決定事項を文書化しない
- 「言った・言わない」で後でトラブルになる

#### 失敗例
```
会議で「来月リリース」と合意
→ 議事録を残さない
→ 1ヶ月後「そんな話は聞いていない」と言われる
```

#### ✅ 対策
- **必ず記録を残す**
  - 会議の議事録を作成
  - 決定事項を文書化
  - 関係者全員に共有

#### チェックリスト
- [ ] 会議の議事録を作成したか？
- [ ] 決定事項を文書化したか？
- [ ] 関係者全員に共有したか？
- [ ] 承認を得たか？

---

### 💣 地雷4：数値データがない

#### 失敗パターン
- 感覚で判断する
- 「多い」「少ない」という主観的な表現
- 効果を数値で示せない

#### 失敗例
```
「業務が非効率です」
→ 数値データがない
→ 「どのくらい非効率なのか？」と聞かれて答えられない
→ 提案の説得力がなくなる
```

#### ✅ 対策
- **必ず数値データを集める**
  - 処理時間、件数、コストなどを測定
  - 「多い」→「50件/日」のように数値化
  - 効果も数値で示す

#### チェックリスト
- [ ] 現状を数値で把握しているか？
- [ ] 効果を数値で示せるか？
- [ ] ROIを計算できるか？

---

### 💣 地雷5：完璧を目指しすぎる

#### 失敗パターン
- 完璧な資料を作ろうとして時間がかかる
- 100%の精度を目指して進まない
- 細かい部分にこだわりすぎる

#### 失敗例
```
「完璧な提案書を作ろう」
→ 細かい部分にこだわりすぎる
→ 期限に間に合わない
→ クライアントに迷惑をかける
```

#### ✅ 対策
- **80%の完成度で進める**
  - まずは全体像を作る
  - 細かい部分は後で改善
  - 期限を優先する

#### チェックリスト
- [ ] 期限を守れるか？
- [ ] 80%の完成度で提出できるか？
- [ ] 細かい部分にこだわりすぎていないか？

## 2. 業務分析での地雷ポイント

### 💣 地雷1：現場の意見を聞かない

#### 失敗パターン
- 経営層の意見だけを聞く
- 現場の実態を把握しない
- 理想と現実のギャップを見逃す

#### 失敗例
```
経営層：「この業務は1時間で終わるはず」
→ 現場の意見を聞かない
→ 実際は3時間かかっている
→ 分析結果が現実と乖離
```

#### ✅ 対策
- **必ず現場にヒアリング**
  - 実際に業務を見学
  - 現場の担当者にインタビュー
  - 理想と現実のギャップを把握

---

### 💣 地雷2：業務フローを正確に把握していない

#### 失敗パターン
- 聞いた話だけでフローを作る
- 実際の業務を見ない
- 例外処理を考慮しない

#### 失敗例
```
「通常のフローだけを把握」
→ 例外処理を考慮しない
→ 実際には例外処理が頻繁に発生
→ 分析結果が役に立たない
```

#### ✅ 対策
- **実際の業務を観察**
  - 業務を見学する
  - 例外処理も含めて把握
  - 複数の担当者に確認

---

### 💣 地雷3：課題の優先順位をつけない

#### 失敗パターン
- 課題を全部並列に扱う
- 優先順位をつけない
- 影響度と緊急度を考慮しない

#### 失敗例
```
「課題が10個あります」
→ 全部を並列に扱う
→ どこから手をつけていいか分からない
→ 結局何も改善できない
```

#### ✅ 対策
- **優先順位をつける**
  - 影響度 × 緊急度でマトリクスを作成
  - 優先度の高い課題から対応
  - 数値で優先順位を判断

## 3. 業務標準化での地雷ポイント

### 💣 地雷1：現場の反発を招く

#### 失敗パターン
- 現場の意見を聞かずに標準化する
- 「今まで通りでいい」という意見を無視する
- 強引に押し付ける

#### 失敗例
```
「標準化マニュアルを作成しました」
→ 現場の意見を聞かない
→ 現場が反発
→ マニュアルが使われない
```

#### ✅ 対策
- **現場の意見を取り入れる**
  - 標準化前に現場にヒアリング
  - 現場の良い点を取り入れる
  - 段階的に導入する

---

### 💣 地雷2：完璧な標準化を目指す

#### 失敗パターン
- 100%の標準化を目指す
- 例外を一切認めない
- 柔軟性がない

```
「すべての業務を標準化する」
→ 例外処理を認めない
→ 現場が使いにくい
→ 標準化が失敗
```

#### ✅ 対策
- **80%の標準化を目指す**
  - 主要な業務を標準化
  - 例外処理も考慮
  - 柔軟性を持たせる

---

### 💣 地雷3：教育・フォローアップがない

- 教育をしない

#### ✅ 対策
- **教育・フォローアップを実施**
  - 研修を実施
  - 定期的にフォローアップ
  - 改善サイクルを確立

## 4. AI技術調査での地雷ポイント

### 💣 地雷1：技術だけで判断する

#### 失敗パターン
- 最新技術だから導入する
- 業務への適用可能性を考慮しない
- コストを無視する

#### 失敗例
```
「最新のAI技術だから導入しよう」
→ 業務に適用できない
→ コストがかかりすぎる
→ 導入が失敗
```

#### ✅ 対策
- **業務への適用可能性を評価**
  - 業務にどう役立つか考える
  - コストと効果のバランスを評価
  - PoCで検証する

---

### 💣 地雷2：セキュリティを考慮しない

#### 失敗パターン
- セキュリティ要件を確認しない
- データの取り扱いを考慮しない
- リスクを評価しない

#### 失敗例
```
「便利なAIツールだから導入しよう」
→ セキュリティ要件を確認しない
→ 機密情報が漏洩するリスク
→ 導入が中止になる
```

#### ✅ 対策
- **セキュリティ要件を確認**
  - データの取り扱いを確認
  - セキュリティリスクを評価
  - コンプライアンスを確認

---

### 💣 地雷3：コストを過小評価する

#### 失敗パターン
- 初期費用だけを見る
- 月額費用を考慮しない
- 運用コストを無視する

#### 失敗例
```
「初期費用は10万円だから安い」
→ 月額費用が50万円
→ 年間で600万円かかる
→ 予算オーバー
```

#### ✅ 対策
- **総コストを計算**
  - 初期費用 + 月額費用 + 運用コスト
  - 3年・5年の総コストを計算
  - ROIを正確に計算
