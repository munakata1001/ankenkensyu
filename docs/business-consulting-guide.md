## 1. 業務分析とは

### 定義
業務の現状を把握し、課題や改善点を特定する活動です。

### 主な目的
- 業務フローの可視化
- ボトルネックの特定
- 非効率な手順の洗い出し
- システム化の要件整理

### 実施手順

1. **現状把握**
   - ヒアリング：関係者へのインタビュー
   - 観察：実際の業務を見学
   - 資料確認：既存のマニュアル・資料を確認

2. **フロー図化**
   - 業務プロセスを図示（フローチャート、BPMN等）
   - 各ステップの担当者・時間・コストを記載

3. **課題抽出**
   - 時間：処理時間が長い箇所
   - コスト：人件費・システム費用が高い箇所
   - 品質：エラー・手戻りが多い箇所

4. **改善案の検討**
   - 優先順位付け（影響度 × 実現可能性）
   - 具体的な改善策を検討

### 成果物例
- 業務フロー図
- 課題リスト
- 改善提案書

### 新人向けのポイント
- まず「なぜその業務があるのか」を理解する
- 現場の人の意見を尊重する
- 数値データを集める（感覚ではなく事実で判断）

## 2. 業務標準化コンサル

### 定義
組織内の業務を統一的なルール・手順に標準化するコンサルティングです。

### 主な目的
- 品質の均一化
- 属人化の解消
- 教育・引き継ぎの効率化
- コスト削減

### 実施内容

1. **現行業務の調査**
   - 部署・担当者間の差異を把握
   - ベストプラクティスの特定

2. **標準化方針の策定**
   - どの業務を標準化するか決定
   - ベストプラクティスを選定

3. **標準マニュアル作成**
   - 手順書の作成
   - チェックリストの作成
   - テンプレートの作成

4. **導入支援**
   - 研修の実施
   - フォローアップ
   - 改善サイクルの確立

### 成果物例
- 業務標準マニュアル
- チェックリスト
- 研修資料
- テンプレート集

### 新人向けのポイント
- 「みんなが同じ手順でできる」状態を目指す
- 完璧を目指さず、まずは80%の標準化を
- 現場の意見を取り入れる

## 3. AI技術動向の調査

### 定義
最新のAI技術・ツール・トレンドを調査し、業務への適用可能性を評価する活動です。

### 調査対象

#### 技術トレンド
- **LLM（大規模言語モデル）**：ChatGPT、Claude、Gemini等
- **生成AI**：テキスト生成、画像生成、コード生成
- **RAG（Retrieval-Augmented Generation）**：社内データと組み合わせたAI
- **エージェント**：自律的にタスクを実行するAI

#### ツール・サービス
- **開発支援**：GitHub Copilot、Cursor、Codeium等
- **APIサービス**：OpenAI API、Anthropic API等
- **プラットフォーム**：Azure OpenAI、AWS Bedrock等

#### 業界事例
- 同業他社の導入事例
- 成功事例・失敗事例
- コスト・効果の実績

#### コスト・制約
- 導入費用（初期・月額）
- 技術的制約（データ量、レスポンス時間等）
- セキュリティ要件

### 調査方法

1. **文献調査**
   - 技術ブログ、論文、公式ドキュメント
   - 業界レポート、市場調査

2. **実証実験**
   - プロトタイプでの検証
   - PoC（概念実証）の実施

3. **ベンダー調査**
   - 提供企業への問い合わせ
   - デモ・トライアルの実施

4. **事例収集**
   - 成功事例・失敗事例の分析
   - 同業他社へのヒアリング

### 成果物例
- 技術動向レポート
- 比較表（ツール・サービス）
- 適用可能性評価
- PoC結果レポート

### 新人向けのポイント
- 技術だけでなく「業務にどう役立つか」を考える
- コストと効果のバランスを評価する
- セキュリティ・リスクも考慮する

## 4. 提案書作成

### 定義
調査・分析結果を基に、クライアント向けの改善提案をまとめた文書です。

### 構成要素

1. **エグゼクティブサマリー**
   - 提案の要点を1-2ページにまとめる
   - 経営層が短時間で理解できる内容

2. **現状分析**
   - 課題・問題点の明確化
   - 数値データで現状を示す

3. **提案内容**
   - 解決策・改善案の提示
   - 具体的な実施内容

4. **効果・メリット**
   - 期待効果（定量的・定性的）
   - 数値目標（KPI）

5. **実施計画**
   - スケジュール（ガントチャート等）
   - 体制・リソース

6. **費用概算**
   - 投資対効果（ROI）
   - コスト内訳

7. **リスクと対策**
   - 想定リスク
   - 対策・回避方法

### 作成のポイント

- **明確な課題設定**：現状の問題を数値で示す
- **具体的な解決策**：抽象論ではなく実行可能な提案
- **ROIの提示**：投資対効果を明示
- **リスクと対策**：想定リスクと対応策
- **視覚化**：図表・グラフで理解しやすく

### 成果物例
- 提案書（PDF/PPT）
- 補足資料（詳細データ）
- デモ・プロトタイプ

### 新人向けのポイント
- 読み手（経営層・現場）を意識して書く
- 専門用語は補足説明を添える
- 図表を活用して視覚的に分かりやすく

## 5. ステークホルダー調整

### 定義
プロジェクトに関わる関係者（ステークホルダー）の意見や利害を調整し、合意形成を図る活動です。

### ステークホルダーとは

**ステークホルダー（利害関係者）の例：**
- **経営層**：経営判断、予算承認
- **プロジェクトマネージャー**：進捗管理、リソース確保
- **開発チーム**：実装、技術判断
- **ユーザー（利用者）**：要件、使いやすさ
- **運用チーム**：保守性、運用負荷
- **営業・マーケティング**：機能要件、リリース時期
- **外部ベンダー**：技術提供、サポート

### なぜ調整が必要か

**よくある対立例：**
- **経営層**：「早くリリースしたい」
- **開発チーム**：「品質を確保するため時間が必要」
- **ユーザー**：「この機能が必須」
- **運用チーム**：「運用負荷を下げてほしい」

→ 調整せずに進めると、後で大きな問題になる

### 調整の手順

1. **ステークホルダーの特定**
   - 誰が関係しているか洗い出す
   - 影響力・関心度を整理

2. **意見・要望の収集**
   - 各ステークホルダーから要望を聞く
   - 背景・理由も確認

3. **対立点の整理**
   - どこで意見が分かれているか明確化
   - 優先順位を確認

4. **調整案の作成**
   - 妥協点を探る
   - 代替案を用意

5. **合意形成**
   - 会議・ミーティングで調整
   - 決定事項を文書化

6. **フォローアップ**
   - 合意内容を共有
   - 変更があれば再調整

### 調整のコツ

#### ✅ やるべきこと
- **早期に調整**：後回しにしない
- **透明性を保つ**：情報を共有
- **代替案を用意**：選択肢を提示
- **記録を残す**：決定事項を文書化

#### ❌ やってはいけないこと
- **一部の意見だけ聞く**：特定のステークホルダーに偏る
- **後回しにする**：問題が大きくなる
- **記録を残さない**：後で「言った・言わない」になる
- **強引に押し切る**：反発を招く

### 実践例

#### 例：機能追加のリリース時期

**状況：**
- 営業：「来月リリースしてほしい」
- 開発：「3ヶ月必要」
- 経営：「できるだけ早く」

**調整の流れ：**
1. **現状共有**：開発工数・リスクを説明
2. **代替案提示**：
   - 案A：来月リリース（機能を削減）
   - 案B：3ヶ月後リリース（全機能）
   - 案C：2ヶ月後リリース（必須機能のみ）
3. **合意形成**：案Cで合意
4. **文書化**：決定事項を議事録に記録

### 開発現場での具体例

#### ケース1：技術選定
- **開発者**：「新しい技術を使いたい」
- **運用**：「既存技術で統一したい」
- **調整**：段階的導入、検証期間を設ける

#### ケース2：スケジュール
- **PM**：「納期を守りたい」
- **開発**：「品質を優先したい」
- **調整**：優先機能を絞り、段階リリース

#### ケース3：予算
- **経営**：「コストを抑えたい」
- **開発**：「外部ツールが必要」
- **調整**：無料ツールで代替、段階的導入

### ステークホルダーマップ（整理ツール）

```
高影響力・高関心：経営層、PM
  → 頻繁にコミュニケーション

高影響力・低関心：経理、法務
  → 必要な時だけ報告

低影響力・高関心：ユーザー、現場
  → 意見を聞き、適切に反映

低影響力・低関心：外部ベンダー
  → 必要最小限の連絡
```

### 新人向けのポイント
- 会議で意見を聞く
- 決定事項をメモする
- 不明点は質問する
- 調整の流れを学ぶ

## 4つの活動の関係性

```
業務分析
  ↓
業務標準化コンサル
  ↓
AI技術動向の調査
  ↓
提案書作成
```

1. **業務分析**で現状を把握
2. **業務標準化**で改善方針を策定
3. **AI技術調査**で適用可能な技術を特定
4. **提案書**にまとめて提示
5. **ステークホルダー調整**で合意形成

## まとめ

### 各活動の要点

| 活動 | 要点 |
|------|------|
| **業務分析** | 現状を把握し、課題を特定する |
| **業務標準化** | 統一的なルール・手順を作る |
| **AI技術調査** | 最新技術を調査し、適用可能性を評価する |
| **提案書作成** | 調査結果をまとめ、改善提案を提示する |
| **ステークホルダー調整** | 関係者の意見を調整し、合意形成を図る |

### 新人が意識すべきこと

1. **質問を恐れない**：分からないことは聞く
2. **記録を残す**：決定事項は必ず文書化
3. **数値で示す**：感覚ではなく事実で判断
4. **関係者を意識する**：誰のための活動か考える
5. **継続的に改善する**：一度で完璧を目指さない
