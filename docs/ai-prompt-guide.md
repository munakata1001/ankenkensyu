## 1. AIプロンプト作成の基本原則

### 良いプロンプトの構成要素

1. **役割の設定**：AIに何をしてほしいか明確に
2. **コンテキスト**：背景情報を提供
3. **具体的な指示**：何を出力してほしいか明確に
4. **出力形式**：フォーマットを指定
5. **制約条件**：守るべきルールを明示

### プロンプト作成の流れ

```
1. 役割を設定
   ↓
2. コンテキストを提供
   ↓
3. 具体的な指示を出す
   ↓
4. 出力形式を指定
   ↓
5. 制約条件を明示
```

## 2. 各活動でのプロンプト例

### 2.1 業務分析用プロンプト

#### ❌ 悪い例
```
業務を分析してください
```

**問題点：**
- どの業務か不明
- 何を分析してほしいか不明
- 出力形式が不明

#### ✅ 良い例
```
あなたは業務コンサルタントです。
以下の業務について分析をお願いします。

【業務概要】
- 業務名：顧客問い合わせ対応
- 担当者：3名
- 1日の処理件数：約50件
- 対応時間：1件あたり平均15分

【現状の課題】
- 対応に時間がかかる
- 回答の品質にばらつきがある
- よくある質問への対応が非効率

【依頼内容】
1. 業務フローを整理してください
2. ボトルネックを特定してください
3. 改善案を3つ提示してください

【出力形式】
- 業務フロー（箇条書き、各ステップの所要時間を含む）
- 課題リスト（優先度順、影響度と緊急度を記載）
- 改善案（効果・実現可能性・コストの観点から）

【トーン】
- 専門的だが分かりやすい
- 数値データを重視
```

### 2.2 業務標準化用プロンプト

#### ✅ 良い例
```
あなたは業務標準化の専門家です。

【現状】
以下の業務について、部署Aと部署Bで手順が異なっています。
標準化マニュアルを作成してください。

【部署Aの手順】
1. 受注確認（5分）
2. 在庫確認（10分）
3. 発注処理（15分）
4. 納品確認（5分）
合計：35分

【部署Bの手順】
1. 受注確認（5分）
2. 発注処理（20分、在庫確認は後で）
3. 納品確認（5分）
合計：30分

【要件】
- 両方の良い点を取り入れる
- 新人でも理解できるレベルで
- チェックリスト形式で
- 各ステップの所要時間を記載

【出力形式】
- 標準業務フロー（フローチャート形式）
- 手順書（各ステップの詳細、注意点を含む）
- チェックリスト（確認項目を箇条書き）
- よくあるミスと対策
```

### 2.3 AI技術動向調査用プロンプト

#### ✅ 良い例
```
あなたはAI技術の調査専門家です。

【調査依頼】
顧客対応業務の効率化のために、AI技術を導入したいと考えています。

【現状の業務】
- 顧客からの問い合わせ対応（メール・チャット）
- 1日50件程度
- 対応時間：1件あたり平均15分
- よくある質問の回答を手動で作成
- 担当者：3名

【調査してほしいこと】
1. 適用可能なAI技術・ツールを3つ提示
2. それぞれの特徴・メリット・デメリット
3. 導入コストの目安（初期費用・月額費用）
4. 導入時の注意点（セキュリティ、データ管理など）
5. 導入ステップ（段階的な導入方法）

【出力形式】
- 比較表（技術名、特徴、コスト、注意点）
- 推奨順位と理由
- 導入ステップ（3ヶ月、6ヶ月、1年の計画）
- 期待効果（時間削減、コスト削減の試算）

【制約条件】
- 日本語対応必須
- セキュリティ要件を満たすもの
- 予算：月額10万円以内を想定
```

### 2.4 提案書作成用プロンプト

#### ✅ 良い例
```
あなたは提案書作成の専門家です。

【クライアント情報】
- 業種：小売業
- 規模：従業員50名
- 課題：在庫管理が非効率、過剰在庫と欠品が発生

【提案内容】
AIを活用した在庫管理システムの導入

【依頼内容】
経営層向けの提案書を作成してください。

【必須項目】
1. エグゼクティブサマリー（1ページ分、要点をまとめる）
2. 現状の課題（数値データを含む、過剰在庫による損失額など）
3. 提案内容（具体的な機能、AIの活用方法）
4. 期待効果（ROIを含む、数値目標を設定）
5. 実施計画（スケジュール・体制・マイルストーン）
6. 費用概算（初期費用・月額費用・ROI計算）

【出力形式】
- マークダウン形式
- 見出し構造を明確に（##、###を使用）
- 箇条書きを活用
- 数値データは表形式で
- 図表の説明を追加

【トーン】
- 専門的だが分かりやすい
- 数値データを重視
- 説得力のある内容
- 経営層が短時間で理解できる

【制約条件】
- 専門用語は避け、新人でも理解できるレベルで
- 具体的な数値データを含める
- リスクと対策も記載
```

### 2.5 ステークホルダー調整用プロンプト

#### ✅ 良い例
```
あなたはプロジェクトマネージャーです。

【状況】
機能追加プロジェクトで、ステークホルダー間で意見が対立しています。

【各ステークホルダーの意見】
- 営業：「来月リリースしてほしい。競合に対抗するため早く必要」
- 開発：「3ヶ月必要。品質を確保したい。テスト期間も必要」
- 経営：「できるだけ早く、でも品質も重要。コストも抑えたい」
- 運用：「運用負荷を下げてほしい。自動化機能を追加してほしい」

【プロジェクト情報】
- 機能：顧客管理システムの新機能追加
- 現在の進捗：設計完了、開発中
- 予算：500万円

【依頼内容】
1. 対立点を整理してください（何が対立しているか明確に）
2. 全員が納得できる調整案を3つ提示してください
3. 各案のメリット・デメリット（各ステークホルダーの視点から）
4. 推奨案とその理由
5. 調整のための会議アジェンダ

【出力形式】
- 対立点の整理表（ステークホルダー別、要望と背景）
- 調整案（案A、案B、案C、それぞれの詳細）
- 比較表（各案のメリット・デメリット、各ステークホルダーへの影響）
- 推奨案と理由
- 会議アジェンダ（議題、時間配分、決定事項）

【トーン】
- 客観的で公平
- 全員の意見を尊重
- 建設的な提案
```

## 4. プロンプト作成のコツ

### 4.1 ✅ 良いプロンプトの特徴

#### 1. 具体的である
- ❌ 「分析してください」
- ✅ 「業務フローを整理し、ボトルネックを3つ特定してください」

#### 2. コンテキストを提供する
- ❌ 「提案書を作って」
- ✅ 「小売業の在庫管理改善の提案書を、経営層向けに作成してください」

#### 3. 出力形式を指定する
- ❌ 「改善案を出して」
- ✅ 「改善案を3つ、優先度順に、効果と実現可能性を含めて提示してください」

#### 4. 制約条件を明示する
- ❌ 「提案書を作って」
- ✅ 「提案書を作成してください。ただし、専門用語は避け、新人でも理解できるレベルで」

#### 5. 数値データを含める
- ❌ 「効率化を提案して」
- ✅ 「現在1件あたり15分かかっている業務を、10分に短縮する提案をしてください」

### 4.2 ❌ 悪いプロンプトの特徴

#### 1. 抽象的すぎる
- 「業務を改善してください」
- 「効率化してください」

#### 2. 情報が不足している
- 「提案書を作って」（何の提案？誰向け？）
- 「分析してください」（何を分析？）

#### 3. 出力形式が不明確
- 「分析結果を教えて」（どの形式？）
- 「改善案を出して」（いくつ？どの形式？）

#### 4. 役割が不明確
- 「業務を分析してください」（誰の視点で？）

#### 5. 制約条件がない
- 「提案書を作って」（予算は？期限は？）

## 8. 新人向けのポイント

### 8.1 まずは基本形から始める
- 完璧なプロンプトを最初から作ろうとしない
- 段階的に改善していく
- まずは「役割 + コンテキスト + 依頼内容」の3要素から

### 8.2 AIの回答を見て改善する
- 期待と違う結果が出たら、プロンプトを修正
- 何度か試行錯誤する
- 良い回答が出たら、そのプロンプトを保存しておく

### 8.3 テンプレートを活用する
- 上記のテンプレートをベースに
- 自分の業務に合わせてカスタマイズ
- よく使うプロンプトはテンプレート化する

### 8.4 具体例を入れる
- 抽象的な指示ではなく、具体的なデータ・例を入れる
- 「効率化」ではなく「15分を10分に短縮」
- 「改善」ではなく「ボトルネックを3つ特定」

### 8.5 出力形式を必ず指定する
- マークダウン、表形式、箇条書きなど
- 見出し構造を指定
- 数値データは表形式で

### 8.6 数値データを含める
- 感覚ではなく、事実（数値）で判断
- 「多い」「少ない」ではなく「50件」「15分」
- ROI、コスト、時間などの数値目標を設定

## 9. 実践演習

### 演習1：業務分析プロンプトを作成

**状況：**
- 業務：商品発注業務
- 担当者：2名
- 1日の処理件数：30件
- 1件あたりの処理時間：20分
- 課題：在庫切れが頻繁に発生

**課題：**
上記の情報を基に、業務分析用のプロンプトを作成してください。

**解答例：**
```
あなたは業務コンサルタントです。

【業務概要】
- 業務名：商品発注業務
- 担当者：2名
- 1日の処理件数：約30件
- 処理時間：1件あたり平均20分

【現状の課題】
- 在庫切れが頻繁に発生
- 発注タイミングが適切でない可能性
```
