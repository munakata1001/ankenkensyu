## 1. 議事録作成の重要性

### なぜ議事録が必要か

1. **記録として残る**
   - 「言った・言わない」のトラブルを防ぐ
   - 後で確認できる

2. **決定事項の共有**
   - 参加者全員が同じ認識を持つ
   - 参加していない人にも情報共有できる

3. **次のアクションが明確になる**
   - 誰が何をいつまでにするか明確
   - 進捗管理の基準になる

4. **プロジェクトの証跡**
   - なぜその決定をしたか記録に残る
   - 後から振り返れる

---

## 2. 議事録に含めるべき基本項目

### 必須項目（必ず含める）

1. **会議情報**
   - 日時（開始時刻・終了時刻）
   - 場所（会議室名、オンライン会議の場合はURL）
   - 会議名・議題

2. **参加者**
   - 参加者名（役職・所属も記載）
   - 議事録作成者名
   - 欠席者（事前に連絡があった場合）

3. **議題・アジェンダ**
   - 議題リスト
   - 各議題の所要時間

4. **決定事項**
   - 何が決定したか
   - 決定した理由（簡潔に）

5. **アクションアイテム**
   - 誰が（担当者）
   - 何を（タスク）
   - いつまでに（期限）

6. **次回会議**
   - 日時・場所（決定している場合）

## 3. 重点的に記録すべきポイント

### ⭐ 最重要：決定事項

**なぜ重要か：**
- 会議の目的は「決定すること」
- 決定事項が不明確だと、後でトラブルになる

**記録のコツ：**
- 「決定：○○を△△する」と明確に書く
- 決定した理由も簡潔に記載
- 反対意見があった場合は、その理由も記載

**例：**
```
【決定事項】
- 機能追加プロジェクトは2ヶ月後のリリースを目指す
  （理由：競合に対抗するため、必須機能のみを優先）
- 予算は500万円以内とする
  （理由：経営層の承認済み予算範囲内）
```

---

### ⭐ 最重要：アクションアイテム

**なぜ重要か：**
- 決定事項を実行に移すために必要
- 誰が何をいつまでにするか明確でないと進まない

**記録のコツ：**
- 「担当者：○○、タスク：△△、期限：××」と明確に
- タスクは具体的に（抽象的な表現を避ける）
- 期限は日付で記載（「来週」ではなく「2026年1月29日」）

**例：**
```
【アクションアイテム】
1. 担当者：田中（開発リーダー）
   タスク：必須機能のリストを作成
   期限：2026年1月25日

2. 担当者：佐藤（PM）
   タスク：スケジュール案を作成
   期限：2026年1月26日
```

---

### ⭐ 重要：議論の要点

**なぜ重要か：**
- なぜその決定をしたか、後から理解できる
- 代替案が検討された場合、その理由が分かる

**記録のコツ：**
- 議論の流れを簡潔に
- 主要な意見・反対意見を記載
- 結論に至った理由を記載

**例：**
```
【議論の要点】
- リリース時期について議論
  - 営業：「来月リリースしてほしい」（競合に対抗）
  - 開発：「3ヶ月必要」（品質確保）
  - 経営：「できるだけ早く、でも品質も重要」
- 結論：必須機能のみを優先し、2ヶ月後リリースで合意
```

---

### ⭐ 重要：課題・懸念事項

**なぜ重要か：**
- 後で問題が起きた時に、早期に気づいていたことが分かる
- リスク管理に役立つ

**記録のコツ：**
- 課題を明確に記載
- 対応方針があれば記載
- 次回までに確認すべき事項があれば記載

**例：**
```
【課題・懸念事項】
- 開発リソースが不足する可能性
  → 対応：外部リソースの確保を検討（担当：佐藤）
- セキュリティ要件の確認が必要
  → 対応：次回までに確認（担当：山田）
```

---

### 記録すべきその他のポイント

1. **数値データ**
   - 予算、スケジュール、目標値など
   - 「約」「だいたい」ではなく、具体的な数値

2. **前提条件**
   - 決定事項の前提条件
   - 「○○が前提」という条件

3. **保留事項**
   - 今回は決定しなかった事項
   - 次回までに検討すべき事項

## 4. 議事録のテンプレート

### 基本テンプレート

```markdown
# 議事録

## 会議情報
- **日時**：2026年1月22日（月）14:00-15:00
- **場所**：会議室A（オンライン：https://zoom.us/xxx）
- **会議名**：機能追加プロジェクト キックオフ会議
- **議事録作成者**：田中太郎

## 参加者
- 山田花子（プロジェクトマネージャー）
- 佐藤次郎（開発リーダー）
- 鈴木三郎（営業部長）
- 田中太郎（コンサルタント）※議事録作成

## 議題・アジェンダ
1. プロジェクト概要の確認（10分）
2. リリース時期の決定（20分）
3. 予算・リソースの確認（15分）
4. 次回会議の日程調整（5分）

---

## 1. プロジェクト概要の確認

### 決定事項
- 機能追加プロジェクトを開始する
- プロジェクト期間：2026年1月22日〜2026年3月22日（2ヶ月）

### 議論の要点
- 経営層から承認を得ていることを確認
- 競合に対抗するため、早期リリースが必要

---

## 2. リリース時期の決定

### 決定事項
- **リリース目標日：2026年3月22日（2ヶ月後）**
- 必須機能のみを優先し、段階的リリースとする

### 議論の要点
- 営業：「来月リリースしてほしい」（競合に対抗）
- 開発：「3ヶ月必要」（品質確保のため）
- 経営：「できるだけ早く、でも品質も重要」
- **結論**：必須機能のみを優先し、2ヶ月後リリースで合意

### アクションアイテム
1. **担当者**：佐藤（開発リーダー）
   **タスク**：必須機能のリストを作成
   **期限**：2026年1月25日

---

## 3. 予算・リソースの確認

### 決定事項
- 予算：500万円以内
- 開発リソース：内部3名 + 外部1名（検討中）

### 議論の要点
- 経営層から承認済みの予算範囲内
- 開発リソースが不足する可能性がある
  → 外部リソースの確保を検討

### 課題・懸念事項
- 開発リソースが不足する可能性
  → **対応**：外部リソースの確保を検討（担当：佐藤、期限：1月26日）

---

## 4. 次回会議の日程調整

### 決定事項
- **次回会議：2026年1月29日（月）14:00-15:00**
- 場所：会議室A

---

## アクションアイテム一覧

| No | 担当者 | タスク | 期限 |
|---|---|---|---|
| 1 | 佐藤（開発リーダー） | 必須機能のリストを作成 | 2026年1月25日 |
| 2 | 佐藤（開発リーダー） | 外部リソースの確保を検討 | 2026年1月26日 |
| 3 | 山田（PM） | スケジュール案を作成 | 2026年1月26日 |

---

## 次回会議
- **日時**：2026年1月29日（月）14:00-15:00
- **場所**：会議室A
- **議題**：
  1. 必須機能リストの確認
  2. スケジュール案の確認
  3. 外部リソースの検討結果報告
```

## 5. 作成のコツ

### ✅ やるべきこと

#### 1. 会議中にメモを取る
- 重要な発言をメモ
- 決定事項をその場で記録
- アクションアイテムをその場で確認

#### 2. 会議終了後すぐに作成
- 記憶が新しいうちに作成
- 24時間以内に作成・共有

#### 3. 簡潔に書く
- 長文ではなく、要点を簡潔に
- 箇条書きを活用
- 読みやすい形式にする

#### 4. 決定事項を明確に
- 「決定：○○」と明確に書く
- 決定した理由も簡潔に

#### 5. アクションアイテムを明確に
- 担当者・タスク・期限を明確に
- 表形式で一覧化

#### 6. 参加者に確認してもらう
- 作成後、参加者に確認依頼
- 誤りがあれば修正
- 承認を得てから正式版として保存

---

### ❌ やってはいけないこと

#### 1. 会議中にメモを取らない
- 「後で思い出す」は危険
- 重要な発言を見逃す

#### 2. 作成を後回しにする
- 記憶が曖昧になる
- 重要な情報を忘れる

#### 3. 主観を入れる
- 自分の意見を混ぜない
- 事実のみを記載

#### 4. 抽象的な表現
- 「来週」「だいたい」ではなく、具体的に
- 「○○について検討」ではなく、「○○を△△する」と明確に

#### 5. 決定事項が不明確
- 「検討することになった」ではなく、「決定：○○」と明確に

## 6. よくある失敗例と対策

### 失敗例1：決定事項が不明確

#### ❌ 悪い例
```
【決定事項】
- リリース時期について検討することになった
```

**問題点：**
- 何が決定したか不明確
- いつリリースするか分からない

#### ✅ 良い例
```
【決定事項】
- リリース目標日：2026年3月22日（2ヶ月後）
- 必須機能のみを優先し、段階的リリースとする
```

---

### 失敗例2：アクションアイテムが不明確

#### ❌ 悪い例
```
【アクションアイテム】
- 田中さんがスケジュールを作成する
```

**問題点：**
- 期限が不明確
- タスクの内容が曖昧

#### ✅ 良い例
```
【アクションアイテム】
1. 担当者：田中（PM）
   タスク：プロジェクトスケジュール案を作成（ガントチャート形式）
   期限：2026年1月26日
```

---

### 失敗例3：議論の要点が長すぎる

#### ❌ 悪い例
```
【議論の要点】
田中さんが「リリース時期について、営業からは来月リリースしてほしいという要望があり、開発からは3ヶ月必要という意見があり、経営からはできるだけ早く、でも品質も重要という意見があり、最終的に必須機能のみを優先し、2ヶ月後リリースで合意しました。」
```

**問題点：**
- 長文で読みにくい
- 要点が伝わりにくい

#### ✅ 良い例
```
【議論の要点】
- リリース時期について議論
  - 営業：「来月リリースしてほしい」（競合に対抗）
  - 開発：「3ヶ月必要」（品質確保）
  - 経営：「できるだけ早く、でも品質も重要」
- 結論：必須機能のみを優先し、2ヶ月後リリースで合意
```

---

### 失敗例4：数値が曖昧

#### ❌ 悪い例
```
【決定事項】
- 予算はだいたい500万円くらい
- 来月リリースを目指す
```

**問題点：**
- 「だいたい」「くらい」が曖昧
- 「来月」が具体的な日付ではない

#### ✅ 良い例
```
【決定事項】
- 予算：500万円以内
- リリース目標日：2026年3月22日
```

## 7. 新人向けのポイント

### 7.1 会議前の準備

- [ ] 議題を確認する
- [ ] 参加者を確認する
- [ ] 議事録テンプレートを準備する
- [ ] メモ用紙・PCを準備する

### 7.2 会議中のポイント

1. **重要な発言をメモ**
   - 決定事項
   - アクションアイテム
   - 数値データ
   - 課題・懸念事項

2. **不明な点は確認**
   - 「これは決定事項ですか？」
   - 「期限はいつですか？」
   - 「担当者は誰ですか？」

3. **その場で確認**
   - アクションアイテムをその場で確認
   - 「担当者は○○さん、期限は××で合っていますか？」

### 7.3 会議後のポイント

1. **すぐに作成**
   - 記憶が新しいうちに作成
   - 24時間以内に作成

2. **テンプレートを使う**
   - 上記のテンプレートを活用
   - 項目を漏らさない

3. **参加者に確認**
   - 作成後、参加者に確認依頼
   - 誤りがあれば修正

4. **共有する**
   - 参加者全員に共有
   - 参加していない関係者にも共有（必要に応じて）

## 9. 議事録の活用方法

### 9.1 プロジェクト管理に活用

- アクションアイテムをタスク管理ツールに登録
- 進捗確認の基準として使用
- 決定事項の確認に使用

### 9.2 次の会議の準備に活用

- 前回の決定事項を確認
- アクションアイテムの進捗を確認
- 保留事項を再検討

### 9.3 関係者への情報共有に活用

- 参加していない関係者にも情報共有
- 決定事項を周知
- プロジェクトの進捗を共有

## 10. まとめ

### 議事録作成で最も重要な3つ

1. **決定事項を明確に**
   - 「決定：○○」と明確に書く
   - 決定した理由も簡潔に

2. **アクションアイテムを明確に**
   - 担当者・タスク・期限を明確に
   - 表形式で一覧化

3. **すぐに作成・共有**
   - 24時間以内に作成
   - 参加者に確認依頼
   - 正式版として保存・共有

### 新人が意識すべきこと

1. **会議中にメモを取る**：重要な発言をメモ
2. **不明な点は確認する**：「これは決定事項ですか？」と確認
3. **すぐに作成する**：記憶が新しいうちに作成
4. **テンプレートを使う**：項目を漏らさない
5. **参加者に確認する**：誤りがあれば修正

### 議事録作成の心構え

- **正確性**：事実を正確に記録
- **簡潔性**：要点を簡潔に
- **明確性**：決定事項・アクションアイテムを明確に
- **迅速性**：24時間以内に作成・共有
